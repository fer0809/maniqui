SISTEMA DE GESTIÓN: FÁBRICA DE MANIQUÍES - DOCUMENTACIÓN TÉCNICA
========================================================================

Este documento explica el funcionamiento integral del sistema, su estructura
de archivos y la lógica detrás del código desarrollado.

1. ARQUITECTURA GENERAL
-----------------------
El sistema utiliza una arquitectura de tres capas:
- PERSISTENCIA (Base de Datos): MariaDB corriendo en Docker.
- APLICACIÓN (Backend): Servidor Node.js con Express.
- INFRAESTRUCTURA: Docker Compose para orquestar los servicios.

2. ESTRUCTURA DE CARPETAS
-------------------------
/base-de-datos
├── backend/            -> El "cerebro". Lógica del servidor y API.
├── database/           -> El "almacén". Scripts SQL y configuración Docker.
├── legacy/             -> Historial. Código antiguo de referencia.
└── README.md           -> Guía rápida de instalación.

3. EXPLICACIÓN DE LA BASE DE DATOS (SQL)
----------------------------------------
Ubicación: `database/`

- creates.sql: 
  Define el "esqueleto" del sistema. Crea dos tablas principales:
  * piezas: Almacena Cabeza, Torso, Brazos y Piernas. Usa ENUM para asegurar
    que solo se ingresen tipos y tallas válidas.
  * maniquies: Almacena el producto terminado. Utiliza CLAVES FORÁNEAS (FK)
    para vincularse con la tabla de piezas. Si una pieza no existe, no se
    puede armar el maniquí.

- inserts.sql:
  Carga 40 piezas (10 de cada tipo) y 5 maniquíes iniciales para que el
  sistema no esté vacío al empezar.

- queries.sql:
  Contiene las 6 consultas específicas pedidas por la cátedra para reportes
  de stock, fechas de fabricación y materiales.

4. EXPLICACIÓN DEL BACKEND (Código Node.js)
-------------------------------------------
Ubicación: `backend/index.js`

El servidor utiliza las siguientes librerías:
- Express: Para crear las rutas (URLs) que acepta el sistema.
- MySQL2: Para que Node.js pueda "hablar" con MariaDB.
- CORS: Para permitir que aplicaciones externas se conecten.

LÓGICA PRINCIPAL:
- GET /api/piezas: Ejecuta un "SELECT * FROM piezas" y devuelve los datos
  en formato JSON para que cualquier app los pueda leer.

- POST /api/maniquies (El proceso de ENSAMBLAJE):
  Es la parte más compleja y segura del código. Utiliza una TRANSACCIÓN:
  1. Inicio: Se abre la transacción.
  2. Validación: Verifica que las 4 piezas existan y que su estado sea "Disponible".
  3. Inserción: Crea el registro en la tabla `maniquies`.
  4. Actualización: Cambia el estado de las 4 piezas a "Ensamblado" (Update).
  5. Commit/Rollback: Si todo salió bien, guarda los cambios. Si algo falló
     (ej. una pieza ya estaba usada), cancela todo para no dejar datos rotos.

5. INFRAESTRUCTURA (Docker)
---------------------------
Ubicación: `database/docker-compose.yml`

Docker nos permite evitar el "en mi máquina no funciona". 
- Crea un servidor MariaDB idéntico para todos los desarrolladores.
- Mapea el puerto 3306 para que el backend pueda entrar.
- Guarda los datos en una carpeta local para que no se borren al apagar la PC.

6. FLUJO DE TRABAJO DEL SISTEMA
-------------------------------
1. El Administrador inicia Docker (`docker-compose up`).
2. Se cargan los scripts SQL (`creates.sql` e `inserts.sql`).
3. Se inicia el servidor Node (`npm start`).
4. El usuario pide "Armar Maniquí" -> El Backend valida -> La BD se actualiza.
